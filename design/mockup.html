「评审」不单独占一行。它是「交付」里的一个子状态——PR 已经准备好、机器人还在提意见——只在开完 PR 之后才出现。

06

两条硬规则

面板上的每个数字都必须对得上它指向的列表，这是这个产品一直守着的规矩。新界面有两个地方容易破规矩，这里先写死：

数字 = 它指向的列表

等你 2
等你答复 · 修复导出等你确认 · PR #124

点「等你的 2」跳到执行页并带上筛选；跳过去的列表必须正好是这两条。如果多出第三条，是筛选错了；如果少一条，是数字算错了。

窄屏只换排布，不丢信息

面板本身就在 DSH 侧边栏里，宽度常常不到 600px。窄屏下右侧的统计列收进标记内部，流程行变成两行，仍然是五格都在。

09

落地顺序

每一步都能单独交付、单独看效果。前两步不动后端，第三步才要补数据。

三个阶段

  1. 流程行 + 流程横条（只用现有数据）
    把 Overview 的四块换成流程行，横条挂在下面。数据来自 GET overview 与 GET threads，后端不改。
  2. 点标记就地展开 + 详情重排
    用 GET tickets/:id 现有字段，把「Worker 刚报告」提到最上面，三个槽位做成小格。
  3. 补时间维度的数据
    「等你的时长」「工作与等待的比例」现在没有存，需要后端在 assignment 上记录开始与结束。这是唯一改后端的一步。

这次不改动

  • 侧边栏的六个标签页，位置与名字都不变。
  • 设置页、来源页、对话页的内部结构不动。
  • 执行、重试、暂停这些按钮的行为不动。
  • Flow 的既有定义（收到、筛掉、评估、接受）保留，只是不再占据 Overview 的主位。
